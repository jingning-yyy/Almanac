# 星历 Almanac · 我的一站

纯本地、零依赖的**个人一站页**：26 个分类 · 534 个网站，内置万年历（农历/节气/节日）、生日提醒（农历/公历/年龄）、纪念日正计时（在一起第 N 天 · 分类筛选）、番茄钟（专注计时 · 四象限待办 · 种树森林）、拖动排序、缩略图模式等完整功能。双击 `index.html` 即可使用，无需安装环境，所有数据保存在本地浏览器。

---

## 快速开始

1. 双击 `index.html`，按 **Ctrl+F5** 强刷一次（确保加载最新版）
2. 首次使用：📅 → 「生日与记录」手动添加，或「导入生日管家」选自己导出的 Excel/CSV 批量录入
3. 日常使用：分类卡片点击直达网站；搜索框即时筛选；📅 万年历查农历/节日/生日提醒

## 分发给别人与更新（部署 GitHub Pages）

推荐部署到 **GitHub Pages**（免费），之后所有人（电脑/手机浏览器）都开同一个网址，不存在"拷文件夹、清缓存"的问题：

1. 注册 [github.com](https://github.com) → 右上角 ＋ → New repository → 名字随意（如 `almanac`），选 **Public** → Create（**不要**勾选 Add README / .gitignore，保持空仓库）
2. 在本项目目录执行（仓库已 `git init` 并完成首次提交；`.gitignore` 已排除隐私与本机文件，`git ls-files` 可随时核对）：
   ```
   git remote add origin https://github.com/<你的用户名>/almanac.git
   git push -u origin main
   ```
3. 仓库 **Settings → Pages** → Branch 选 `main` + `/ (root)` → Save
4. 等一两分钟，得到网址 `https://你的用户名.github.io/almanac/` ——手机、电脑浏览器都开它即可

**以后更新**：本地改代码 → 版本三处 +1（`index.html` 的 `?v=N`、`js/version-check.js` 的 `APP_VER`、`version.json` 的 `{"v":N}`）→ `git add -A && git commit -m "vN" && git push` → 别人刷新即最新；**开着旧版的人会自动弹"发现新版本"提示条**，点"立即刷新"即可（`js/version-check.js` 实现，本地 file:// 打开时自动跳过检测）。

**数据各自独立**：纪念日/心情/图片存在每个人自己设备的浏览器里，互不相通也不同步到服务器；两人之间同步纪念日用「导出」→ 传文件 → 「导入」。

**隐私与本机文件已由 `.gitignore` 排除**：`data/`（账号明文密码、亲友生日、纪念日）、`.idea/`（含本机路径）、`__pycache__/`、`startup_log.txt`、`srv_out.txt` 不会进入任何提交，`git ls-files` 可随时核对。⚠️ 若改用网页拖拽上传，`.gitignore` 对其**无效**，必须按文件白名单逐项上传。`server.py` 与两个 `.bat` 无隐私内容、会随仓库发布，仅本机有用，介意可从提交中移除。仓库作者身份已设为中性名（仓库级 `git config`，未动全局），避免提交记录暴露个人邮箱。

### 磁盘数据文件夹（data/）

日常使用：**双击 `启动星历.bat`**（已在运行则直接开页面，没运行则后台启动服务器再开页面；`关闭星历.bat` 可停掉后台服务器）。或手动：`python server.py`（或双击）启动本地服务器并访问 `127.0.0.1:8630`。此时各账号数据会**自动镜像为 data/ 目录下的真实 JSON 文件**：

```
data/
├── 用户名.json       ← 每用户一个文件（该账号全部数据打包）
├── default.json
├── accounts.json    ← 账号表（用户名 → 密码哈希）
└── current.json     ← 当前登录身份
```

- 资源管理器里直接可见、可整体拷贝迁移（把 data/ 文件夹拷给别人即可带走数据）
- 页面运行期间每 5 秒自动同步 + 关闭页面时立即保存
- 双击 index.html（file://）打开时无磁盘同步，数据仍在浏览器（用账号面板的导出/导入迁移）
- 部署到 GitHub Pages 用 git 推送时 `.gitignore` 已排除 `data/`，生日记录不会公开；网页拖拽上传则不受 `.gitignore` 保护，勿用。

## 数据来源与合并机制

页面加载时按以下结构运行时合并（app.js 的 `allCategories()`）：

```
data.js（内置精选 254 站，18 分类）
  ↑ 合并
  ├── data-itab.js（270 站，15 分组）—— 经 NAV_ITAB_MERGE 映射并入：
  │     travel→旅游出行  Finance→金融财经  程序员→开发技术  Tool→实用工具
  │     learn→学习教育  外网|刊→新闻资讯  主页→常用推荐  产品/设计→产品与设计
  │     其余保持独立：摸鱼 官网 Job waiting 考试升学 数据资源 凹3
  ├── data-bookmarks.js（10 站，凹3 独立）—— 与内置分类同名自动按名并入
  └── localStorage 自定义网址（nav_custom_sites）
```

- **同名自动并入**：导入数据中与已有分类同名的分组自动并入该分类（无需映射）
- **NAV_ITAB_MERGE / NAV_BOOKMARKS_MERGE**：控制跨名归并关系，改映射即可拆分/合并分组
- 修改任何数据文件后刷新即生效，互不影响

## 常用维护任务

### 增删网址
编辑 `js/data.js`（或 data-itab），按文件内注释格式增删，刷新生效。

### 批量导入生日
万年历内「导入生日管家」选 Excel/CSV。如需自动导入可重建 `js/auto-import.js`（定义 `window.__AUTO_IMPORT` 数组）并在 `index.html` 引入——**该文件会随部署一起公开，切勿写入真实生日**。

### 修改已录入的生日
记录列表点 **✎**：可改名称、类别、农历↔公历、月日、出生年份、备注。补出生年份后显示"满 N 岁"。

### 农历生日转固定公历
记录列表点 **⇄**：按出生年份换算成对应公历日期并固定（可逆）。无出生年份会提示先补填。

### 更新版本号（重要）
`index.html` 中所有 css/js 引用带 `?v=N`。**改了任何 css/js 后必须统一 +1**，否则浏览器缓存导致"改了没生效"。当前 v1.0（公开发布起点，此前内部迭代到 v73）。番茄钟的 `TOMATO_VER`（在 `js/tomato.js`）也要跟着 +1。版本号按数值比较（1.0 → 1.1 → … → 1.9 → 2.0），**不要用 1.10**（数值上小于 1.9，更新提示会误判）。

### 清理重复生日
旧版本自动导入的缺陷可能产生过重复条目（同名不同历法）。手动 ✕ 删除多余的一条即可——修复后的机制保证不会再复活。

## 农历引擎与已知边界

- `solarlunar.js` 覆盖 1900–2100，数据表定稿自开源 solarlunar 项目并已逐字节校验
- 提供农历↔公历互转（生日转换功能依赖 `lunar2solar`）
- 已知锚点验证：2026 春节=2/17、2026 中秋=9/25、1990 闰五月
- 手机触屏不支持拖动（系统限制），排序/归类需电脑端
- 农历生日按"农历当天对应公历日"提醒（传统过法）；想固定阳历请点 ⇄ 转公历
- 本地测试服务器：`python $TEMP/nav_server.py` → 127.0.0.1:8630（no-cache 头，脚本见会话记录）；file:// 使用无需服务器
